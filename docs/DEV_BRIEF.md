# Company Policy — Developer Brief (read fully before coding)

**Game:** *Company Policy*, a top-down 2D action roguelike (corporate satire, stylised pixel gore, 18+).
**Full design spec:** `docs/SPEC.md`. It is the source of truth: honour every requirement in it and exceed it where you can. Never cut scope.

## Engine decision (deviation from spec D31, approved by the producer)
Unity can't run in our build environment, so the game is **TypeScript plus a custom Canvas2D pixel renderer**, bundled by Vite.
- PC: an Electron Windows installer.
- Android: a Capacitor APK/AAB.
- Both are built by GitHub Actions.

Everything else in the spec still applies: 640×360 internal resolution with integer scaling, 60 fps, data-driven balancing, deterministic seeds, and so on.

## Hard rules
1. **No external assets.** Every sprite, tile, icon, font glyph, sound and music note is generated by our own code at runtime: canvases for art, Web Audio for sound. No image or audio files, no fonts from the internet, and no copyrighted melodies, real brands, logos or real product names. "CorpOS" is our invented OS.
2. **Pixel art discipline.** Integer coordinates, no anti-aliasing (`imageSmoothingEnabled = false`), and a 1 px dark outline on characters and enemies (`OUTLINE` in `src/art/palette.ts`). Tiles are 16×16. Characters are about 32×48 px; bosses go up to 96×96. The view is top-down 3/4.
3. **The telegraph colour is reserved.** `TELEGRAPH` `#ff2bd6` (and the colourblind alternative `#ffe600`) must never appear in any other art.
4. **Determinism.** Gameplay randomness uses `Rng` / `RngStreams` from `src/core/rng.ts`, never `Math.random()`. Purely cosmetic effects may use `fxRng`.
5. **Language.** UK English spelling in all player-facing text ("colour", "organisation", "programme"). Tone is deadpan corporate satire, dark comedy and profanity (18+). No explicit sexual content. No real drugs giving benefits; caffeine and fictional items only. No real-world extremist symbols. No real company, product or person names.
6. **Stay in your files.** Only create or modify the files your task assigns you. If you need a change in a shared file (`src/core/*`, `src/render/*`, `src/game/world-types.ts`, `src/data/ids.ts`, `src/data/tables.ts`, the contract exports in `src/art/*.ts` or `src/audio/audio.ts`), **don't make it**. List the exact change you need in your final report. Additive exports in your own files are always fine.
7. **Keep contracts.** Contract files define exported function signatures (for example `bakeCharacter`, `generateFloor`, `registerAudio`). Your implementation must keep those exact signatures so other modules compile against them.
8. **Typecheck clean.** Run `npx tsc --noEmit` before finishing. Your files must have zero errors. Errors in other people's in-progress files aren't yours; ignore them, but mention them.
9. **Don't commit or push.** The lead integrates and commits.
10. **Performance.** Target 60 fps on a 2020 mid-range Android phone. Bake or cache sprites, and never re-render static art every frame. Avoid per-frame `getImageData`.

## Project layout
```
src/core/      app.ts (loop, scenes, settings), input.ts, rng.ts, math.ts, events.ts, storage.ts, settings.ts
src/render/    renderer.ts (640×360 integer scaling, camera, shake, zoom), canvas.ts (pixel helpers, outline), font.ts (bitmap font: drawText/measure/wrap)
src/art/       palette.ts, characters.ts, items.ts, env.ts      (procedural art)
src/audio/     audio.ts (contract + proxy); engine implementation registers via registerAudio()
src/data/      ids.ts (canonical IDs), tables.ts (CSV-driven balancing), csv/*.csv, text/* (writing)
src/game/      world-types.ts (FloorMap contract), gen/ (procgen), gameplay systems
src/scenes/    boot.ts, dev/ (visual QA galleries), game scenes
src/ui/        CorpOS UI framework + HUD
tools/         shot.mjs (headless screenshot), soak test, asset export
```

## Visual QA (mandatory for art and UI work)
- A dev server normally runs at `http://localhost:5173`. If it doesn't, start one with `npx vite --port 5173 &`. Use a different port if you run your own, e.g. `npx vite --port 5180 &` plus `URL=http://localhost:5180/`.
- Add a gallery file `src/scenes/dev/<yourname>.ts` that calls `registerDev('<name>', () => new YourScene())`. It's auto-loaded; open it with `#dev=<name>`.
- Screenshot it with `node tools/shot.mjs scratch/<file>.png "dev=<name>" 2000`, then **look at the PNG** with your image-reading tool. Iterate until it looks like professional hi-bit pixel art (references: Enter the Gungeon, Katana Zero, Hotline Miami readability). Console errors are printed by the tool.
- The renderer draws into `app.renderer.f` (the final 640×360+ frame). Use `app.renderer.W/H`.

## Key APIs
- `app` (from `src/core/app.ts`): `app.renderer`, `app.input`, `app.settings`, `app.push/pop/replace/reset(scene)`, `app.time`.
- `Scene` interface: `{ enter?, exit?, resume?, update(dt), render(), transparent? }`. Fixed step: `dt = 1/60`.
- Font: `drawText(g, text, x, y, { color, scale, align, shadow, outline })`, `measure(text, scale)`, `wrap()`, `drawWrapped()`. Glyph height 9 (cap height 7), line height 10.
- Canvas helpers: `paint(w, h, g => ...)`, `withOutline(canvas, col)`, `silhouette`, `shade(hex, amt)`, `mixHex`, `ellipse`, `line`, `rect`, `px`, `Sprite`, `drawSprite`, `drawSpriteRot`.
