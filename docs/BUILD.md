# Building and releasing Company Policy

The game is TypeScript + Vite (Canvas2D). It ships as:

| Target | Wrapper | Output |
| --- | --- | --- |
| Windows 10/11 x64 | Electron + electron-builder | `CompanyPolicy-Setup-<version>.exe` (NSIS installer), `CompanyPolicy-Portable-<version>.exe`, `CompanyPolicy-<version>-win-x64.zip` |
| Linux / Steam Deck (testing) | Electron AppImage | `CompanyPolicy-<version>-linux-x64.AppImage` |
| Android 10+ (API 29+) | Capacitor 8 | `CompanyPolicy-<version>-android.apk` (sideload) and `.aab` (Play) |
| Browser | Vite | `dist/` |

Everything is built by GitHub Actions on every push; you only need a local toolchain for development.

## Prerequisites

* Node.js 22 or newer (Capacitor 8 requires it) and npm.
* Android only: JDK 21 and the Android SDK (platform 36, build-tools 36.0.0), or just Android Studio.

```bash
npm ci
```

On a machine that cannot download the Electron binary (for example a locked-down container) install with
`ELECTRON_SKIP_BINARY_DOWNLOAD=1 npm ci`; you then cannot run or package Electron there.

## Day-to-day development

```bash
npm run dev          # Vite dev server on http://localhost:5173 (browser)
npm run typecheck    # tsc --noEmit
npm run build        # production bundle in dist/
npm run electron:dev # build, then open the desktop shell on the built game
# Hot reload in the desktop shell: run `npm run dev`, then set CP_DEV_URL=http://localhost:5173 and `npx electron .`
```

Desktop shell behaviour (`electron/main.cjs`, `electron/preload.cjs`): fullscreen by default, F11 or Alt+Enter toggles,
minimum windowed size 960x540, no menu bar, DevTools disabled in packaged builds, single instance, background throttling
disabled, strict CSP. The game is served from a privileged `app://game/` origin so ES modules and `localStorage` work.
Saves are written atomically (temp file then rename) to `<userData>/saves/` through `window.cpNative`:

* Windows: `%APPDATA%\Company Policy\saves\`
* Linux: `~/.config/Company Policy/saves/`

## Building locally on Windows (primary)

```powershell
npm ci
npm run dist:win
```

Output is in `release\`: the NSIS installer (choose install directory, desktop and Start-menu shortcuts), the portable
exe, and `win-unpacked\` (zip it for a Steam depot). The installer is unsigned unless you provide a code-signing
certificate (`CSC_LINK` / `CSC_KEY_PASSWORD` environment variables, see the electron-builder docs); expect a Windows
SmartScreen warning ("More info" then "Run anyway") for unsigned builds.

## Building locally on Linux

```bash
npm ci
npm run dist:linux            # release/CompanyPolicy-<version>-linux-x64.AppImage
chmod +x release/*.AppImage && ./release/*.AppImage
```

On Steam Deck: copy the AppImage over, mark it executable, add it to Steam as a non-Steam game (Desktop Mode), and set
the Steam Input layout to "Gamepad" (the game reads the standard Chromium Gamepad API). The AppImage disables the
Chromium sandbox automatically because the setuid helper cannot run inside an AppImage mount.

## Building the Android APK/AAB locally

```bash
npm ci
npm run android:build    # vite build -> cap sync android -> gradle assembleRelease bundleRelease
```

Outputs: `android/app/build/outputs/apk/release/app-release.apk` and `android/app/build/outputs/bundle/release/app-release.aab`.
Open the `android/` folder in Android Studio to run on a device or emulator. After changing web code run `npm run cap:sync`.

Android project notes (everything is committed under `android/`):

* `minSdk 29` (Android 10), `compileSdk`/`targetSdk 36` (Capacitor 8 default, current Google Play requirement), pure
  WebView app so it is 64-bit automatically.
* Landscape only (`sensorLandscape`), immersive fullscreen re-applied on focus, screen kept on, content drawn into the
  display cutout (`shortEdges`), hardware accelerated.
* Touchscreen and gamepad are declared `required="false"` so controller-only devices can install it.
* `versionName` comes from `package.json` `version`; `versionCode` = major\*10000 + minor\*100 + patch (override with
  the `CP_VERSION_CODE` environment variable). Bump the version in `package.json` for every release you upload to a store.
* Icons and splash are generated by `npm run icons` (`tools/make-icons.mjs`, original pixel art drawn in code) and committed.
* The web layer receives `cp-back` (Back button / gesture), `cp-pause` and `cp-resume` window events from
  `src/platform/android.ts` (`initAndroid()` must be called once at startup).

## Installing the APK (sideload)

1. Download `CompanyPolicy-<version>-android.apk` from the latest Actions run (artifact `CompanyPolicy-Android-APK`) or
   from a GitHub Release, and copy it to the phone.
2. Open it from a file manager or the browser. Android will ask you to allow installs from that app
   (Settings, Apps, Special access, Install unknown apps); allow it for the app you used and go back.
3. Tap Install. Play Protect may warn about an app from an unknown developer; choose "Install anyway".
4. Or from a PC with USB debugging on: `adb install -r CompanyPolicy-<version>-android.apk`.

Updates install over the top as long as the same signing key was used, so keep using the same key for any given test
group (see below).

## Signing

The workflow picks the Android signing key like this:

1. If the repository secrets `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD` and `ANDROID_KEY_ALIAS` exist
   (and optionally `ANDROID_KEY_PASSWORD`, otherwise the keystore password is used), the build is signed with that key.
   Create the base64 with `base64 -w0 my-upload-key.jks` and paste it into the secret.
2. Otherwise it uses the committed **sideload key** `android-signing/sideload.keystore`
   (alias `sideload`, store and key password `companypolicy-sideload`).

**The committed sideload key is public. It is for sideloading and test distribution only.** Anyone could sign an
APK with it, so never treat it as proof of origin. **Do not publish to Google Play with it.** For Play, create your own
upload key, enrol in Play App Signing (Google holds the real app-signing key; you only keep the upload key), put the
upload key in the four secrets above and upload the `.aab`. Local builds use the same logic through the `CP_KEYSTORE_FILE`,
`CP_KEYSTORE_PASSWORD`, `CP_KEY_ALIAS`, `CP_KEY_PASSWORD` environment variables.

Regenerating the sideload key (invalidates in-place updates for everyone who installed with the old one):

```bash
keytool -genkeypair -keystore android-signing/sideload.keystore -storetype PKCS12 -alias sideload \
  -keyalg RSA -keysize 2048 -validity 36500 -storepass companypolicy-sideload -keypass companypolicy-sideload \
  -dname "CN=Company Policy Sideload, OU=Test Distribution, O=Intellidrift, C=GB"
```

## CI (`.github/workflows/build.yml`)

Triggers: every push to any branch, tags `v*`, and manual `workflow_dispatch` (with an optional `release` checkbox).

| Job | Runner | What it does | Artifact |
| --- | --- | --- | --- |
| `web` | ubuntu | `npm ci`, non-blocking `tsc --noEmit`, `npm run build` | `CompanyPolicy-Web` |
| `windows` | windows-latest | build, `electron-builder --win` (NSIS + portable), zip of unpacked app | `CompanyPolicy-Windows` |
| `linux` | ubuntu | build, AppImage, headless Xvfb smoke test of the packaged app (non-blocking) | `CompanyPolicy-Linux-AppImage` |
| `android` | ubuntu | Temurin 21, Android SDK 36, `cap sync`, `gradlew assembleRelease bundleRelease`, `apksigner verify` | `CompanyPolicy-Android-APK`, `CompanyPolicy-Android-AAB` |
| `release` | ubuntu | only for tags `v*` or a manual run with `release=true`: creates or updates a GitHub Release with every artifact | GitHub Release |

To cut a release: bump `version` in `package.json`, commit, then `git tag v1.0.1 && git push origin v1.0.1`.
Artifacts of ordinary runs are kept for 30 days (Actions tab, open the run, scroll to Artifacts).

## Store integration notes (stubs)

* **Steam (PC):** needs a Steamworks App ID and a depot. Upload the unpacked Windows build (`release/win-unpacked` or the
  zip) with SteamPipe (`steamcmd +run_app_build`). Steam achievements, leaderboards and Cloud need a native addon such as
  `steamworks.js` bridged through the preload script, plus `steam_appid.txt` for local testing; none of this is wired up
  yet. Steam Cloud can simply point at the `saves/` folder. For Steam Deck use the Windows build through Proton
  (spec 10.4) and keep the Linux AppImage for testing only.
* **Google Play (Android):** needs a Play Console developer account, a new app with package name
  `com.intellidrift.companypolicy`, Play App Signing, the Data safety form and a privacy policy (spec 10.5). Upload the
  `.aab` signed with your upload key. Play Games Services (leaderboards, saved games) and Play Billing (the one-time unlock) are not
  integrated yet; they would be added as Capacitor plugins and surfaced to the game through `src/platform/`.
* The package name (`com.intellidrift.companypolicy`) and Electron `appId` are identical so the identity is consistent
  across stores. Changing it after a store release is not possible.
